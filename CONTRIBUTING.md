# Contributing

Thank you for your interest in pacod-cms.

## Code contributions

pacod-cms does not accept contributions at the moment: no pull requests, patches, documentation
changes, translations or template sets. Pull requests will not be reviewed or merged. This may
change later; this file will say so when it does.

## Bug reports and feature suggestions

Both are welcome. Open an issue in the repository's **Issues** tab. Search the existing issues
first: if yours is already there, add what you know to it instead of opening a new one.

A bug report helps most when it gives:

- the version or commit, and which part is affected: the public site (`pacod-cms-site`), the
  studio (`pacod-cms-studio`), the shared core (`pacod-cms-core`), a template set, or the
  deployment files (compose, Caddy);
- how you run it: a developer machine, stage or production, and the browser, if the bug is in what
  a page shows;
- the steps to reproduce, and what happens compared with what should happen;
- the error messages and log lines.

A feature suggestion helps most when it says:

- what you are trying to do, and what stops you today;
- how you would expect the studio or the site to behave;
- what you use instead, if anything.

Issues are public. Remove passwords, tokens, keys and readers' or authors' personal data from
everything you post. Placeholders are enough.

## Security vulnerabilities

Do not report a vulnerability in a public issue. Use GitHub's private vulnerability reporting: the
repository's **Security** tab, then **Report a vulnerability**.
